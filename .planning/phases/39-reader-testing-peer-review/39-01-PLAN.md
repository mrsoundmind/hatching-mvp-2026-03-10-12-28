# Phase 39 — Reader Testing Peer Review Mode · Plan 39-01 (server) · SHIPPED 2026-07-31

**Branch:** `feat/v2.2-intelligence-fixes` (nothing merged). Server-only; the UI half is Plan 39-02.

## Goal (plain language)

When a Hatch writes a reader-facing document (PRD, blog post, marketing email, landing copy, brief,
research/analysis writeup, process doc), a **fresh reader** reviews it having seen ONLY the finished
document plus the project name and who it's for, NEVER the chat that produced it. It flags, in plain
words, every place an outsider would get lost, catching "this only makes sense if you wrote it."

## What shipped in 39-01 (server)

1. **Doc-type gate** — `isReaderFacingDocType()` + `READER_FACING_DOC_TYPES` in `shared/deliverableTypes.ts`.
   10 prose types reviewed; 6 structured/internal types (tech-spec, user-stories, content-calendar,
   project-plan, data-report, custom) deliberately excluded. Fails closed on unknown types.
2. **The fresh reader** — `server/ai/readerTestReviewer.ts`. Context-blind prompt (READ-02), cross-model
   (Groq, a different family than the DeepSeek/Gemini writer → no self-preference), free, fail-safe
   (any LLM/parse failure → `null`, never blocks). Returns quote-anchored annotations
   `{quote, issue, severity, suggestion, charOffset}` + `readableWithoutContext` + `summary`.
   `countResolvedAnnotations()` powers the READ-04 resolved signal.
3. **Persistence** — new nullable JSONB column `deliverable_versions.reader_test` (`shared/schema.ts`),
   `storage.updateDeliverableVersionReaderTest()` (both MemStorage + DatabaseStorage). `db:push` applied live.
4. **Wiring** — `reviewDeliverableForReaderTest(deliverableId)` in `deliverableGenerator.ts` orchestrates
   run + persist onto the current version. Called two ways ("Both", per user decision):
   - **Auto**: fire-and-forget after `generateDeliverable()` for reader-facing types (never blocks the user).
   - **Manual re-run**: `POST /api/deliverables/:id/reader-test` (ownership-checked), e.g. after a revision.
5. **READ-04** — on re-run, `resolvedFromPrevious` counts how many of the prior version's flagged phrases
   are gone; the existing frozen-rubric score delta (`scoreIteration`) is the second half of the signal.

## Design choices (carried from v2.2 Phase D LLM-as-judge)

- Cross-model + blind + fail-safe, same rationale as `server/autonomy/peerReview/llmJudge.ts`.
- Deliverables never called peer review before this — 39-01 is a NEW reviewer on the document side, not
  an extension of the autonomous-task peer review. The two paths stay independent.
- Quote-anchoring (not literal line numbers): robust to markdown reflow; `charOffset` lets the UI highlight.
